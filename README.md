# StoryFlow

Phase 1: minimal backend — SQLite schema (via Alembic) and a concurrency-safe job
queue (atomic claim, worker ownership/lease, active-job dedupe, stale recovery).
Phase 0 (bootstrap) remains intact.

## Backend

```
backend/
  storyflow/database.py     engine/session + pragmas (WAL, busy_timeout, FK) + sqlite3 datetime adapter
  storyflow/models.py       WorkflowSession, RunnerInstance, PipelineJob, RunnerAttempt (+ enums, indexes)
  storyflow/queue.py        enqueue/claim/renew/complete/fail/requeue/waiting_capacity/recover
  storyflow/runners.py      runner state helpers
  storyflow/config.py       Settings (db url, lease/timeout/attempts defaults)
  alembic/                  migrations, revision 0001_storyflow_initial
  tests/                    22 pytest tests (deterministic time, real thread race)
  .venv/                    python 3.13 + SQLAlchemy 2.0.54 + Alembic 1.20.0 + pytest
```

Concurrency model (see `storyflow/queue.py`): every ownership mutation runs in a
single-writer `BEGIN IMMEDIATE` transaction on a raw connection; jobs are finalized
only by the exact `(worker_id, claim_token)` that claimed them; a partial unique
index keeps one active job per `dedupe_key`; stale recovery touches only processing
jobs whose lease actually expired. `waiting_capacity` is not a business failure
(attempts/outcome untouched).

## Layout

```
backend/                  backend project (placeholder)
frontend/                 frontend project (placeholder)
config/                   configuration (placeholder)
scripts/                  tooling / smoke tests
runtime/                  generated runtime state (gitignored)
bootstrap.py              fetch pinned upstream dependencies (idempotent)
sources.lock.json         source of truth for upstream repo + revision pins
start-app.bat             check bootstrap, then (later) start the app
external/                 generated full clones (gitignored)
skills/                   generated skill copies (gitignored)
```

`external/`, `skills/` and `runtime/` are generated by `bootstrap.py` and are
not StoryFlow source — they are gitignored.

## Bootstrap

```bat
python bootstrap.py          :: clone/fetch upstreams, checkout pinned revisions
python bootstrap.py --check  :: verify state only, no downloads (exit 1 if out of sync)
start-app.bat                :: checks bootstrap, runs it if needed
```

- Subtitle_supperVip → `external/subtitle_suppervip` (pinned commit, no source edits).
- Skills-Import → mirrored in `external/_cache/skills-import`; only the two pinned
  skills are copied into `skills/` (full repo is not duplicated).
- Idempotent: correct revisions are never re-downloaded; wrong revisions are
  reset to the pinned revision; errors fail loudly.
